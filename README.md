# Server Mods

基于 React、TypeScript、Vite 和 Express 的 Minecraft 模组面板。面板读取服务器上的模组目录，按 SHA-512 在 Modrinth 上识别模组，分为双端、服务端和客户端三类展示与下载；后台提供仅密码的管理员登录（密码由环境变量设置）、游戏环境配置以及每个模组的开关、分类与绑定管理。背景图形均为本地 SVG，模组图标来自 Modrinth，加载失败时回退为本地图形。

## 开发

需要 Node.js 22.12+（已在 Node.js 24 环境验证）。

```sh
npm install
npm run dev
```

启动前须设置管理员密码 `ADMIN_PASSWORD`（见下方环境变量）。开发时可在项目根目录创建 `.env`（已被 Git 忽略），写入一行 `ADMIN_PASSWORD=至少八个字符的密码`。

开发命令同时启动 Vite（默认 `http://localhost:5173`）和 API（默认 `http://127.0.0.1:3001`），Vite 将 `/api` 代理到后端。

## 检查、测试与生产运行

```sh
npm run typecheck
npm test
npm run build
npm start
```

生产运行默认地址为 `http://127.0.0.1:3001`，由同一个服务提供前端和 API。前端输出到 `dist`，后端输出到 `dist-server`。`npm run preview` 同样启动完整生产服务，需要先构建。

环境变量（也可写在启动工作目录的 `.env` 中，已设置的环境变量优先）：

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `ADMIN_PASSWORD` | 无，**必填** | 管理员密码，8–256 个字符；未设置或长度不符时服务输出一行说明后退出 |
| `HOST` | `127.0.0.1` | 服务监听地址；需要局域网访问时设为 `0.0.0.0` |
| `PORT` | `3001` | API／生产服务端口；修改开发端口时同步调整 Vite 代理 |
| `DATA_DIR` | `.panel-data` | 认证、配置和模组状态数据目录，相对于启动工作目录；须在静态文件目录之外 |
| `PUBLIC_ORIGIN` | 当前请求的协议与 Host | 反向代理后的完整外部来源，例如 `https://mods.example.com`；不含路径 |
| `TRUST_PROXY` | `loopback` | 反向代理的地址或网段，逗号分隔，例如 `172.18.0.0/16`；仅在设置 `PUBLIC_ORIGIN` 时生效 |

反向代理部署时，将前端和 `/api` 一起代理到服务，并设置 `PUBLIC_ORIGIN` 为用户访问的来源。HTTPS 来源启用 Secure Cookie。开发时不必设置该变量；若设置，必须与 Vite 页面来源一致。

设置 `PUBLIC_ORIGIN` 后，来自 `TRUST_PROXY` 的连接按 `X-Forwarded-For` 识别真实客户端地址，认证限流因此按客户端分别计数；其他来源携带的该请求头一律忽略。代理与服务同机时保持默认即可；代理位于其他主机或容器时，将 `TRUST_PROXY` 设为代理的地址或所在网段，且不要让客户端绕过代理直连服务。

每个数据目录只运行一个后端进程。数据目录中 `panel.json` 保存面板配置，`mods.json` 独立保存模组状态，两者都采用串行、原子替换；管理员密码只来自 `ADMIN_PASSWORD`，启动时在内存中计算 scrypt 哈希，不写入数据目录；旧版本 `panel.json` 中注册产生的密码哈希会被忽略，并在下次保存时移除。数据目录不通过 HTTP 公开，也不提交 Git。`panel.json` 损坏会导致启动失败，不会自动清空配置；`mods.json` 损坏只会重新扫描目录，不影响面板配置。

运行用户需要模组目录的**写权限**：面板会按分类在模组目录与其中的 `client-only` 子目录之间移动文件，并通过增删 `.disabled` 后缀实现开关。面板不会上传、删除或覆盖模组文件；目标位置已有同名文件时移动失败并在后台显示原因，源文件保持原位。权限问题的提示方式见下方“权限与异常提示”。

本机若 npm 启动脚本指向失效的全局安装，可直接调用有效的 npm CLI：

```powershell
& 'C:\Program Files\nodejs\node.exe' 'C:\Program Files\nodejs\node_modules\npm\bin\npm-cli.js' run dev
```

## 功能

- 首次启动（尚未完成配置）时不显示前台：页面直接打开无法关闭的“管理员登录”，输入 `ADMIN_PASSWORD` 后进入两步引导，依次设置模组目录、Minecraft 和加载器。引导完成后留在模组管理器，前台从此对访客正常显示。引导期间退出或会话过期会回到登录窗口。
- 完成配置后，点击前台“管理”输入密码登录，不使用用户名，登录后进入 `#/admin` 的模组管理器。
- 目录使用服务器机器上的绝对路径。输入框右侧“检查”真实列出当前层级的文件与子目录，并通过创建再删除一个临时文件测试写权限（目录只读时给出警告，仍可保存），成功后变为“确认”。空目录有效，修改路径须重新检查，保存时再次验证可读取。
- 支持 Fabric、Forge、NeoForge、Quilt。版本可从官方在线列表选择或手动输入，加载器版本留空表示不指定。Minecraft 默认只列正式版，可开启快照。版本请求有 8 秒超时、1 小时缓存；网络错误时可以重试或手动输入。
- 两步引导整体保存；中途退出，下次重新开始。已保存的游戏与加载器版本同步到前台标题，目录始终只对已登录管理员可见。
- 后台右上角提供设置、退出和主题切换。设置可修改目录与版本、前台显示分类、切换主题。修改密码需更改 `ADMIN_PASSWORD` 并重启服务，重启会使全部会话失效。
- 会话使用 HttpOnly、SameSite Cookie，最长 24 小时，服务重启后重新登录。认证请求每个客户端地址每 15 分钟最多 10 次；写操作校验来源。
- 对话框支持 Escape、键盘焦点约束与关闭后的焦点恢复；提供窄屏布局与减少动态效果支持。主题通过 localStorage 按浏览器保存，存储不可用时仍可在内存切换。

## 模组识别、分类与开关

前后台固定显示**双端、服务端、客户端**三个列表。面板扫描模组目录根层级和其中的 `client-only` 子目录，只处理 `.jar` 与 `.jar.disabled`，不递归其他目录，也不跟随符号链接。

**识别与分类**：文件稳定 1 秒后计算 SHA-512，批量提交 [Modrinth 哈希接口](https://docs.modrinth.com/api/operations/versionsfromhashes/)匹配具体版本。分类优先取版本的 `environment`，其次取项目的 `environment`，再退回旧的 `client_side`／`server_side` [字段](https://docs.modrinth.com/api/operations/getproject/)：

| 环境 | 分类 |
| --- | --- |
| `client_only`、`client_only_server_optional`、`singleplayer_only` | 客户端 |
| `server_only`、`server_only_client_optional`、`dedicated_server_only` | 服务端 |
| `client_and_server`、`client_or_server`、`client_or_server_prefers_both` | 双端 |

旧字段仅一端为 `required` 时归该端；一端 `unsupported`、另一端明确支持时归另一端。缺失、未知、冲突以及跨多个分类的项目级环境都归双端。未识别的文件使用文件名和本地图标，位于根目录时默认双端、位于 `client-only` 时默认客户端，不会因此被移动。管理员手动指定的分类始终优先。

**目录与后缀**：分类决定目录，开关决定后缀，两者互不覆盖。

| 分类 | 开启 | 关闭 |
| --- | --- | --- |
| 双端／服务端 | `example.jar` | `example.jar.disabled` |
| 客户端 | `client-only/example.jar` | `client-only/example.jar.disabled` |

`client-only` 是普通子目录，面板不额外阻止加载。关闭只添加 `.disabled`，重新开启只去掉末尾一个。更改分类保持开关，更改开关保持分类、绑定与配置；识别流程不会自动开启管理员关闭的模组。关闭的模组仍留在后台所属列表并标记状态，前台隐藏，下载接口返回 404。

**监测**：启动和切换目录时扫描，`fs.watch` 防抖触发，并每 10 秒核对补偿漏报。读取期间文件发生变化会重新排队。文件移动与改名串行执行，先独占创建目标再重命名，因此不会覆盖已有文件。开关与移动只影响后续加载，不会卸载已在运行的模组。

**权限与异常提示**：目录级问题显示在后台模组列表顶部，并在新出现时弹出提示；单个文件的问题显示在对应条目上。问题解决后提示自动消失，服务日志同步记录出现与恢复。

| 情况 | 处理 |
| --- | --- |
| 模组目录无法读取、不存在或未挂载 | 列表暂停更新，保留全部条目与设置，不视为“文件已删除” |
| 模组目录或 `client-only` 不可写 | 启动和切换目录时检测；只读期间每次核对重新检测，恢复后提示消失 |
| 移动或改名失败（权限、占用、同名冲突） | 条目显示原因，之后每次核对自动重试，障碍解除后自动完成 |
| 模组文件无法读取 | 条目显示原因并停止“识别中”，随定时核对重试 |
| `mods.json` 无法写入 | 提示设置可能在重启后丢失，每次核对重试保存 |
| `mods.json` 存在但无权读取 | 不覆盖该文件，本次运行不保存模组设置，提示修复后重启 |
| `panel.json` 无法写入 | 相应操作返回明确原因，例如数据目录无写权限或磁盘已满 |
| 前台下载时文件无法读取 | 返回说明原因的错误，而非中断连接 |
| 启动时数据目录无权限、端口被占用或无权监听 | 输出一行说明后退出 |

**绑定与下载**：哈希匹配到具体版本且项目元数据获取成功时显示“已绑定 Modrinth”，下载跳转到与本地哈希一致的 Modrinth 文件地址，而非最新版或主文件。取消绑定保留项目元数据、分类和开关，清除精确版本并停止自动重绑，可随时“重新识别绑定”。未绑定的模组可手动填写项目 ID／slug（校验项目存在且类型为模组）和下载地址；关联只提供展示信息，不推断版本、不改变分类或开关。未配置地址时由面板直接提供文件。

**网络异常**：请求失败与哈希未命中分开处理；请求会去重、批量提交，超时和限流按退避重试。断网不会清除绑定、改变开关或移动已有文件，只在对应条目上显示原因。

模组状态保存在数据目录的 `mods.json` 中，按模组目录分别存储，切换目录互不影响。内部改名与移动保持条目 ID；同名文件内容变化会重新识别版本并保留管理员设置；外部改名只在哈希唯一匹配时继承条目，内容相同的重复文件分别列出。

前台“下载全部”按当前列表顺序，每隔 300 毫秒发起一个已开启的双端模组下载，不包含客户端或服务端分类。按钮小字提示“需要多重下载权限”；请在浏览器中允许本站下载多个文件。页面不检测权限、不弹窗，也无法确认文件是否实际保存。下载名单在点击时固定，触发期间禁止重复点击，离开首页会停止尚未发起的下载。列表加载中、加载失败或没有双端模组时按钮不可用。

整合包打包与下载、模组上传、删除、自动更新版本和依赖安装均不在当前范围内。

## 接口与代码

共享类型位于 `shared/types.ts`；前端组件位于 `src`；后端位于 `server`。

| 接口 | 说明 |
| --- | --- |
| `GET /api/auth/status` | 登录与引导完成状态 `{ authenticated, configured }` |
| `POST /api/auth/login` | 登录，正文 `{ password }` |
| `POST /api/auth/logout` | 注销当前会话，正文 `{}` |
| `POST /api/admin/directory/check` | 检查目录，正文 `{ path }` |
| `GET /api/admin/config` | 获取完整配置，尚未完成时返回 `null` |
| `PUT /api/admin/config` | 保存 `modsDirectory`、`minecraftVersion`、`loader` 和可空 `loaderVersion` |
| `GET /api/admin/versions/minecraft` | Minecraft 正式版与快照 |
| `GET /api/admin/versions/loaders?loader=fabric&minecraft=1.20.1` | 对应加载器版本 |
| `GET /api/public/config` | 仅公开游戏与加载器信息，未配置时为 `null` |
| `GET /api/public/mods` | 已开启模组的前台列表，含修订号 |
| `GET /api/public/mods/events` | SSE 推送修订号，触发列表重新获取 |
| `GET /api/public/mods/:id/download` | 校验开启状态后跳转或下载 |
| `GET /api/admin/mods` | 全部模组及管理状态 |
| `PATCH /api/admin/mods/:id` | 独立更新 `enabled`、`side`（`null` 表示自动）或未绑定时的 `projectId`、`downloadUrl` |
| `POST /api/admin/mods/:id/unbind` | 取消精确绑定，正文 `{}` |
| `POST /api/admin/mods/:id/resolve` | 显式重新识别绑定，正文 `{}` |

除状态、登录和 `public` 接口外均需有效会话。写操作须带 `Origin` 和 `Content-Type: application/json`。首次或变更目录时，保存之前须完成目录检查。公开响应只包含已开启条目，不含绝对路径、管理配置或内部错误详情；下载只按条目 ID 查找文件，拒绝任意路径、目录越界和符号链接。前后台都通过同一个 SSE 修订号刷新，重连后重新获取完整列表，刷新不覆盖未保存的表单。

自动化测试使用隔离的临时数据目录、模拟版本源和模拟 Modrinth，不依赖外网或现有管理员密码；覆盖认证、会话、目录权限、配置持久化、版本适配、表单交互，以及全部端侧枚举与旧字段组合、三种分类与两种开关的组合、外部改后缀与改名、文件冲突与权限失败、目录不可用与状态无法保存时的提示和自动恢复、目录切换与重启恢复、公开列表与下载的权限边界。
